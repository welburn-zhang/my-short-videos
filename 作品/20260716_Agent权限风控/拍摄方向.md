# Agent 权限风控｜拍摄方向

## 当前阶段

- 本文只确认拍摄方向、内容层次和展示方式，暂不进入完整脚本。
- 后续涉及封面文案、标题、开头台词和完整口播时，再按项目流程单独确认。

## 一、这条视频真正要讲什么

这条视频不把重点放在「GPT-5.6 到底有多危险」，也不渲染 AI 会突然失控。

真正想讲的是：越来越多人开始让 Agent 直接操作文件、代码、数据库和各种工具，但很多人在交任务前，没有先想清楚它能做什么、做到哪一步必须停下来问自己，以及出了问题怎么恢复。

核心提醒：

> 把 AI 当助手前，先给它划好边界。

整条视频围绕三层保护展开：

> 先定规矩，再限制能力，最后留好后路。

对应三个具体动作：

1. 在 `AGENTS.md` 里写清长期规则。
2. 在 Agent 工具里开启沙箱，并设置关键操作的审批方式。
3. 提前做好电脑、文档和代码备份。

## 二、开头方向：从热点切入，但不把热点讲成结论

开头先放近期 X 上几位用户反馈本地文件、项目文件或数据库被 Agent 意外删除的截图，用这些画面建立风险感。

表达时需要保留边界：

- 这些是不同用户公开发布的个案反馈，不直接等同于已经证实的普遍性产品故障。
- 重点不是说模型「自己发疯」，而是它在执行任务时做了超出用户预期或授权范围的动作。
- 热点只负责提出问题，后面马上转到普通人能做什么。

开头完成的任务：

1. 告诉观众，Agent 已经不只是回答问题，它真的能操作文件和工具。
2. 点明风险：能力越强，越不能只靠一句「你别乱动」。
3. 给出本期承诺：用三层保护，把 Agent 的风险控制在自己能承受的范围内。

正式写脚本前，需要再次核对三张 X 截图的原帖、发布时间和完整上下文，避免把个案说成大范围事故。是在 GPT 5.6 模型更新之后，在最近的这一周，有三位开发者在 X 上说，Soul 的模型删除了他们本地的一些文件

## 三、第一层：在 AGENTS.md 里先定规矩

### 这一层解决什么问题

`AGENTS.md` 是 Agent 每次进入项目后默认要读取的长期工作规则。它适合放稳定、反复适用的要求，而不是只在某一次聊天里临时提醒。

需要讲清楚：`AGENTS.md` 是行为规则，不是技术上的强制隔离。它能降低误操作，但不能替代沙箱和备份。

### 建议展示的规则类型

#### 1. 任务范围

- 为完成当前任务，可以自动读取、创建和修改相关项目中的文件，包括跨项目操作，不需要逐项请求人工确认。
- 所有操作必须与当前任务直接相关，不能因为发现了其他问题就顺手扩大修改范围。
- 普通文件编辑应尽量保持可恢复，并在完成后汇报修改了哪些文件、产生了什么影响。

这里不按项目目录一刀切。真实任务经常需要读取和修改多个项目，如果每跨一个目录都让用户确认，Agent 的效率会明显下降。更合理的做法是：普通读写默认自动执行，真正可能造成明显损失的操作才由人工确认。

#### 2. 高风险操作

- 删除文件或文件夹，清空文件、整文件替换或不可恢复地覆盖原内容，大范围批量移动、重命名或修改文件，执行前先列出对象、影响和恢复方式，等待用户本人明确确认。
- 强制回退代码、清理未提交内容、强制推送，写入或删除正式数据库数据，上传敏感资料，以及扩大系统权限或开启完全访问，也属于必须人工确认的高风险操作。
- 不确定某个文件是否仍有用途时，先询问，不自行寻找“替代对象”继续执行。
- 优先使用可恢复的方式，例如保留副本、使用版本控制或移入回收站。

这里不要笼统地写「覆盖文件必须确认」，因为正常编辑并保存文件也可能被理解成覆盖。真正需要人工确认的是清空、整文件替换，以及导致原内容难以恢复的覆盖操作。这类长期有效的规则适合写在 `AGENTS.md` 里；某一次任务还有额外要求时，再在聊天输入框里补充。

#### 3. 数据库、账号和凭据

- 并不是完全不能接触正式数据库，而是只通过已经配置好的 MCP、只读账号或最小权限账号访问。
- 查询真实数据时，先限定表、字段和时间范围，避免一次性拉取无关用户信息。
- 涉及写入、删除、批量更新正式数据时，必须再次确认。
- Token、密码、密钥不要明文粘贴到聊天记录或 `AGENTS.md`，应放在系统钥匙串、环境变量或专门的密钥管理工具中；Agent 只调用，不在输出中展示。

#### 4. 失败时怎么处理

- 找不到指定文件、对象或目标时，停止并说明现状，不自行挑选相似对象代替。
- 命令失败后先分析原因，不通过扩大权限、强制删除或批量重试来“把任务做完”。
- 发现任务可能影响范围外的数据时，先返回计划和风险，再等待决定。

### 屏幕展示建议

不做长篇配置教学，只在 Codex 中打开一份简短的 `AGENTS.md`，重点框出三句话：

1. 与当前任务相关的普通读写可以自动执行，包括跨项目操作；不得顺手扩大范围。
2. 删除、清空、整文件替换和大范围批量修改前，先列清单并等待本人确认。
3. 找不到指定对象时停止询问，不得自行选择替代对象继续执行。

## 四、第二层：开启沙箱和审批

### 这一层与 AGENTS.md 的区别

- `AGENTS.md`：告诉 Agent 应该怎么做。
- 沙箱：从技术上限制 Agent 能直接操作到哪里。
- 审批：当 Agent 想越过当前边界时，决定是由人确认，还是交给自动审核。

可以用一句更通俗的话：

> 规则是跟它约法三章，沙箱是给工作区域加一道门，审批是门口的门禁。

### 这次用 Codex 做具体示例

当前建议展示的设置：

- **批准策略：按请求**。需要额外权限时发起请求，不直接放开全部权限。
- **沙盒设置：工作区写入**。可以读取文件，也可以编辑当前工作区，但工作区之外的写入需要额外授权。
- **自动审核：关闭**。需要越过边界时，优先由用户自己判断，而不是让系统代替审批。
- **完全访问权限：关闭**。不让 Agent 默认编辑电脑上的任意文件。

同时要讲清两个容易误解的地方：

1. 「工作区写入」不等于工作区内绝对安全。Agent 仍可能修改或删除工作区里的文件，因此还需要规则和版本记录。
2. 沙箱不能保证永远不出错，它主要是缩小出错时可能影响的范围。

### 关于网络权限

网络访问也属于能力边界。需要查资料、安装依赖或调用在线工具时可以开启，但如果任务只处理本地资料，可以关闭或在需要时再授权。视频里不展开成复杂教程，只提醒观众：网络、外部目录、正式数据，都应该按任务需要开放，而不是一次全部放开。

### 其他 Agent 工具怎么理解

这条视频只用 Codex 做具体演示，不分别教学 Claude Code、TRAE、WorkBuddy 等产品。普通人只需要记住三个通用问题：

1. 它默认能读写哪些文件夹？
2. 超出范围时，会不会先向我申请？
3. 有没有「完全访问」「自动执行」「跳过确认」一类高风险开关？

不同产品的按钮名称可能不同，但判断逻辑相同。

## 五、第三层：提前做好备份

备份虽然放在视频的第三层讲，但必须在 Agent 开始工作之前就准备好。它不是出事后再做，而是最后一道恢复防线。

### 1. 电脑备份

- 普通用户可以使用 Mac 的时间机器，或其他带历史版本的整机备份方案。
- 建议接入独立硬盘并开启自动备份，不要只依赖自己偶尔想起来手动复制。
- 云盘同步不完全等于备份：如果误删操作被同步，云端文件也可能跟着消失；要确认服务是否支持回收站和历史版本。

### 2. 文档备份

- 重要文档优先放在支持历史版本和回收站的工具里。
- 大改前保留一个原始版本，命名中写清日期或版本。
- 定期检查历史版本是否真的能恢复，而不是只看到「已同步」就认为安全。

### 3. 代码和项目备份

- 使用 Git 记录每一次明确的修改节点，完成一小段工作就及时提交。
- 再把提交推送到 GitHub、GitLab 或其他远端仓库。即使本地项目损坏，也能从远端重新拉取。
- 需要提醒观众：只有已经被 Git 跟踪、提交并成功推送的内容，才真正存在远端备份里。
- 尚未提交的修改、被忽略的文件、大体积素材、本地数据库和配置文件，不会因为执行了 `git push` 就自动得到保护。
- Token、密码和真实用户数据不能为了备份而直接提交到代码仓库。

## 六、整条视频的内容顺序

1. **热点画面**：连续展示三张 X 用户反馈截图。
2. **问题转向**：不讨论模型有多危险，讨论使用 Agent 前为什么要做权限风控。
3. **第一层——规则**：录屏展示 `AGENTS.md` 中三条核心规则。
4. **第二层——沙箱与审批**：展示 Codex 的「按请求、工作区写入、自动审核关闭、完全访问关闭」。
5. **第三层——备份**：用三个简单画面说明电脑备份、文档历史版本、Git 提交并推送远端。
6. **总结**：规则降低乱做的概率，沙箱缩小能影响的范围，备份保证出了问题还能恢复。

## 七、拍摄形式

- 真人口播为主，截图和录屏作为证据，不做复杂的假文件删除实验。
- 前段使用三张 X 截图制造真实感，但不长时间讲事件细节；具体截图由用户在后期剪辑时加入。
- `AGENTS.md` 使用真实文件截图，只展示三条观众能抄走的规则。
- Codex 设置使用当前配置画面，并在关闭「自动审核」后重新截图或录屏；只展示关键开关，不讲安装、登录或完整配置过程。
- 电脑备份部分由用户提供截图，分别展示 Mac 和 Windows 可以使用或找到的备份软件。
- 普通文档备份和代码项目备份不拍复杂设置页，使用简单图标配字幕解释。
- 每一层都回答一个问题：我该怎么说、它实际上能做什么、出错后我怎么恢复。

## 八、表达与审核风险

- 不把个案描述成「大量用户都被删文件」或已经证实的普遍性漏洞。
- 不说 `AGENTS.md` 能强制阻止所有误操作。
- 不说开启沙箱后文件就绝对不会被删除，只说它能缩小影响范围。
- 不把「完全访问」讲成绝对不能用；只有任务确实需要、影响范围明确且已有备份时，才临时开启，用完后关闭。
- 避免把视频做成外网工具下载安装教程；前 10 秒不要堆叠过多产品名、官网名和技术词。
- 三张 X 截图正式使用前，需要遮挡无关个人信息，并保留账号名、发布时间和原帖上下文所需的信息。

3. Codex 设置画面使用当前配置，并在关闭「自动审核」后重新截图或录屏。
4. 三张 X 截图由用户在后期剪辑时自行加入。
5. 电脑备份由用户提供 Mac 和 Windows 的备份软件截图；普通文档和代码项目使用简单图标配字幕解释。
