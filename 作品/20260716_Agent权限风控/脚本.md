## 脚本文案（拍摄版，剪映分批录制）

最近一周，三位开发者和AI创业者在使用gpt5.6模型后，都遇到了本地文件和数据被删除的情况。
那反倒提醒了我一件事：以前的 AI 判断错了，可能只是给你一个错误的答案；而现在的 Agent 判断错了，真的会动你的本地文件，从而造成很严重的影响。越聪明的模型有时候为了把任务做完，甚至会主动做出一些，违背用户原意的动作，诶不过别担心，这类情况的发生概率还是很低的。
那我们怎样在不牺牲效率的情况下，更放心地把任务交给 Agent呢，其实只要做好这3件事就可以了。

第一件事，在 `AGENTS.md` 里把规矩写清楚。如果不知道什么是AGENTS.md，可以看我这条视频。
现在我的md里有三条限制。
第一，与当前任务相关的普通读写可以自动执行，包括跨项目操作，但不能顺手扩大范围。这里给agent圈定了一个执行范围。
第二，删除文件、清空内容、文件替换和大范围批量修改，必须先把清单列出来，等我本人确认。这里说的不是正常编辑文件，而是那些做错以后很难恢复的操作，必须我人工审核。
第三，找不到指定对象就停下来问，不准自己挑一个长得差不多的继续做。开头说的3位开发者的例子，问题就出在这里。
那你还可以继续加一条：正式数据库的写入和删除、强制回退代码、上传敏感资料，也必须回来问你。`
AGENTS.md` 能减少 Agent 自己猜的概率，但它毕竟是一份行为规则，更像和它做了约法三章，所以我们还要继续做第二件事。

第二件事，打开沙箱，别一上来就给它整台电脑的权限。诶，有朋友会问，什么是沙箱？你可以把它理解成先给 Agent 划出一个工作区，它可以在里面正常干活，想超出这个范围，就要申请额外权限。
那这里我用 Codex 举例，我会把沙盒设置成“工作区写入”，让它可以在当前工作区正常读写文件；
然后在聊天框这里有“更改权限”的选项，日常使用“替我审批”就可以了，当 Agent 需要额外权限时，系统会交给另一个审核 Agent 判断，而不会向你确认，减少频繁打断从而降低效率。那“完全访问权限”尽量保持关闭，这样它就不能修改电脑里的任意文件，减少删除文件的风险。
如果你正在处理特别特别重要的资料，最好先复制一份，放进单独的工作区，再把“替我审批”换成“请求批准”，这样Agent在修改资料时会先让你自己确认，降低风险。

第三件事，大多数人都会忽略的一点，一定一定要提前把电脑备份做好。
如果你用的Mac电脑， 可以打开“时间机器”，Windows 可以使用“文件历史记录”或系统里的备份功能，最好接一块独立硬盘，让它自动留下历史版本。
那普通文档，尽量放在支持回收站和历史版本的工具里。
而代码项目就用 Git，做完一段及时提交，再推送到远端代码仓库。如果本地项目真出了问题，还能从远端仓库重新拉下来。

看完今天这条视频，赶紧去检查一下自己的 Agent ，再把那三条规则写进全局 `AGENTS.md`，还有一定一定一定要及时做电脑备份。好了，记得点赞收藏+关注，后面我会分享更多适合小白观看的AI内容，我们下期再见，拜拜。
