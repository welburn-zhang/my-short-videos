# C22B｜MCP 是什么

## 拍摄定位

- **系列位置**：Codex 官方最佳实践第 5 条的下半部分，承接 C22A「Skill 是什么」。
- **核心问题**：Skill 能教 AI 怎么做事，但如果资料在文档、表格、日历、任务系统或浏览器里，AI 还需要能接触这些真实工具和资料。
- **一句话方向**：MCP / 连接器解决的是「AI 去哪里拿资料、能操作哪些工具」的问题。

## 切入点和方向

- 从一个真实工作闭环切入，不从协议解释开始。
- 推荐主案例：整理一周工作信息。
  - 没有连接工具：你要把会议纪要、表格、待办和聊天记录复制给 AI。
  - 有 MCP / 连接器：AI 可以在授权范围内读取对应资料，再按你的要求整理成周报或待办清单。
- 备用案例：
  - 学习方向：连接文档库或资料来源，读取最新材料后生成学习摘要。
  - 项目方向：连接任务系统和文档，汇总项目进度、风险和下一步。
  - 设计 / 开发方向：连接浏览器、设计稿或代码托管平台，检查页面问题或读取项目上下文。

## 和 Skill 的关系

- **Skill**：告诉 AI 这件事应该按什么流程做。
- **MCP / 连接器**：告诉 AI 可以去哪里拿资料、能调用哪些工具。
- 最好用一句人话讲清楚：Skill 像工作流程，MCP 像工具接口；一个管「怎么做」，一个管「去哪拿、怎么连」。
- 不要把二者讲成上下级，也不要说谁替代谁。更准确的表达是：真实工作流里，它们经常配合使用。

## 演示建议

- 第一段展示普通方式：把资料复制粘贴给 AI，资料多了就乱，也容易漏。
- 第二段展示连接后的方式：AI 能读取授权资料，自动汇总成固定格式。
- 第三段再点一下和 Skill 的配合：MCP 负责取资料，Skill 负责按你的工作习惯整理输出。
- 画面最好用脱敏演示数据，不展示真实公司文档、私聊、日程和任务细节。

## 需要注意的点

- 对外表达可以先说「连接工具」或「连接资料来源」，再补充专业名叫 MCP。
- 不要做 MCP 服务清单，不讲「装了哪些 MCP」，而讲「连接之后多了什么真实能力」。
- 不要演示账号登录、授权细节、安装命令和外网入口。
- 必须提醒权限边界：AI 能看什么、能改什么，应该由你授权；涉及真实资料时要脱敏。
- 这条适合放在 Skill 后面拍，因为观众先理解「流程复用」，再理解「连接资料和工具」，接受度更高。
