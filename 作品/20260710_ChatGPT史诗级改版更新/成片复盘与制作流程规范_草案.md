# ChatGPT 史诗级改版｜成片复盘与短视频制作流程规范（草案）

## 一、成片检查结论

- 成片文件：`定稿3.0.mov`
- 成片时长：`06:37.57`
- 画面规格：`1920 × 1080 / 30fps`
- 内容结构：真人开场 → 更新背景 → 三个入口 → 模型与推理档位 → Sites 与插件 → 周报案例 → 学习计划案例 → 真人收口。
- 核心呈现方式：**真人建立陪伴感，分镜图解释抽象关系，真实录屏提供证据，大字与标注负责降低理解成本。**

这条视频里最值得复用的不是某一张插图，而是几种固定画面模板和切换规则。后续应该先把这些模板和资产清单锁定，再进入生图和剪辑。

## 二、这条成片形成的视觉语言

### 1. 五种固定画面模板

#### A｜全屏真人口播

- 用在开头、强判断、个人反应和结尾。
- 人物居中，以表情、手势和口播为主体。
- 重点词可以在人物前后弹出，但一屏只强调一组大字。
- 本片使用位置：开头约前 20 秒、最后约 12 秒。

#### B｜左侧长方形真人 + 右侧信息卡

- 左侧真人约占画面宽度的 `30%—32%`。
- 右侧最多放 `2—3` 个信息板块。
- 用在开头预告、目录、需要真人持续讲解的总结画面。
- 不适合放完整桌面录屏，右侧空间更适合大字和少量卡片。

#### C｜左下圆形人物 + 右侧主内容

- 圆形人物约占画面宽度的 `12%—15%`。
- 主内容占右侧及上方约 `72%—78%`。
- 是整条视频使用频率最高的模板。
- 可承载分镜图、截图、模型卡、流程图和真实录屏。
- 圆形人物使用原始真人视频，不用生成式头像替代。

#### D｜章节大字卡

- 一张画面只放一组标题，用于内容转段。
- 本片使用了“ChatGPT 5.6 模型”“更新的重要功能”“案例演示”“第二个案例”“周报 → PPT”“手机效果演示”等节点。
- 建议停留 `1.5—3 秒`，不在标题卡上继续堆解释。

#### E｜全屏录屏 / 截图 + 人物小窗

- 产品操作、表格、文档和网页结果必须以真实录屏为主。
- 人物小窗固定在左下角，不能频繁移动。
- 关键操作通过鼠标高亮、局部放大、红圈或箭头解释。
- 一段录屏只聚焦一个动作，不把完整操作过程无剪辑地全部保留。

### 2. 统一视觉规则

- 主背景：深靛蓝和深蓝黑。
- 主要强调色：紫色、冰蓝。
- 警告与错误：红色或红紫色。
- 正文字幕：白色，放在底部中央。
- 关键词：黄色、橙色或高亮白色，但同一画面只使用一种强调色。
- 分镜图：烟熏玻璃卡片、柔和边缘光，不使用复杂游戏 HUD 和过多粒子。
- 每张画面只讲一个核心关系；同时可见的主模块原则上不超过 `3` 个。
- 底部约 `18%—22%` 作为字幕安全区，除左下圆形人物位外不放关键信息。

### 3. 成片节奏规律

- 开头先真人强判断，再切目录画面；没有一上来就长时间展示软件界面。
- 抽象关系使用分镜图，例如 App 合并、模型选择、推理档位、插件分支、复制文档导致的问题。
- 具体操作使用真实录屏，例如入口切换、模板生成、导入数据、发布 Sites 和手机访问。
- 同一张基础画面可以停留较长时间，但必须通过点亮、放大、红圈、局部标注或文字逐步出现，让画面每 `3—6 秒` 发生一次信息状态变化。
- 章节之间用短标题卡换气，不连续堆叠多个复杂信息图。
- 结尾回到全屏真人，减少信息量，让观众明确视频已经结束。

## 三、本轮制作暴露的问题

### 1. 脚本确认后，没有先锁定完整画面清单

脚本虽然已经完成，但“哪句话用真人、哪句话用截图、哪句话需要生图”没有一次性确定，导致进入剪辑后不断发现缺图。

### 2. 风格确认与正式生图混在一起

一边选择主视觉，一边制作正式分镜，容易把测试图、正式图和通用模板混在同一目录里，后期难以判断应该使用哪个版本。

### 3. 分镜图承担了过多文字任务

生图模型直接生成大量文案时，容易出现错字、英文过多和档位顺序错误。以后应把“结构与物件”交给生图，把可变文字交给剪映叠加。

### 4. 通用模板准备得太晚

左侧长方形真人 + 右侧录屏、左下圆形人物 + 右侧录屏，这两种模板应该在一开始就准备好，而不是剪辑过程中才补。

### 5. 真实录屏清单没有提前逐条验收

案例演示涉及旧周报、新数据、Template Creator、PPT 模板、Visualize、Sites、电脑端和手机端。没有提前列清单，容易剪到某句话时才发现缺少对应录屏。

## 四、以后统一使用的制作流程

## 阶段 1｜脚本定稿

脚本需要同时满足：

- 口播正文已经确认，不再大幅改结构。
- 所有产品名、数据、模型档位和强结论已经核实。
- 演示案例和模拟数据已经准备完成。
- 口播按语义段落拆分，不按一句一行拆分。
- 文档底部保留一份不含画面说明的纯脚本文案，方便提词和复制。

完成标志：用户明确回复“脚本定稿，可以做分镜”。

## 阶段 2｜画面拆解

脚本定稿后，先为每个语义段落确定以下字段：

| 字段 | 必填内容 |
| --- | --- |
| 段落编号 | `S01、S02……` |
| 对应台词 | 这张画面承接的原文 |
| 画面目的 | 强调、解释、证明、演示、转场或收口 |
| 画面类型 | 真人 / 录屏 / 截图 / 生图 / 大字卡 |
| 固定布局 | A、B、C、D、E 中的一种 |
| 核心主体 | 一张图里最重要的物件或关系 |
| 后期叠字 | 需要在剪映添加的准确文字 |
| 建议时长 | 预计停留秒数 |
| 素材来源 | 已有文件、待录屏或待生图 |
| 状态 | 待准备 / 已完成 / 已验收 |

拆解规则：

- 一个语义关系对应一张图，不按照每句话生成一张图。
- 能用真实录屏证明的内容，不用生成式插画替代。
- 只有抽象关系、前后对比和转场才优先生图。
- 画面类型和布局必须在生图前确定，不能边生成边决定。

完成标志：形成一份完整的分镜清单，用户确认后进入下一阶段。

## 阶段 3｜资产清单锁定

分镜确认后，一次性生成三类清单。

### A. 真人素材

- 全屏真人口播。
- 左侧长方形半身口播。
- 左下圆形人物视频。
- 结尾真人口播。

原则：尽量使用同一条高清真人素材，通过裁切适配三种版式，保证服装、光线和状态统一。

### B. 真实录屏与截图

- 每一项操作必须写清开始状态、操作动作和结束结果。
- 录屏统一使用 `1920 × 1080` 或更高分辨率。
- 录制前关闭通知，检查隐私信息和平台审核风险词。
- 鼠标移动要慢，关键点击前后各停留约 1 秒。
- 同时录制结果全貌和关键区域近景，给剪辑留空间。

### C. 生图与通用模板

- 先准备两张通用模板：B 布局和 C 布局。
- 再生成脚本真正需要的抽象解释图。
- 测试阶段只生成 3 张风格样张，用户选定 1 张后锁定颜色、材质、光效和人物位。
- 风格锁定后一次性批量生成正式图片，不再边剪边试风格。
- 正式文件统一命名：`scene-01.png、scene-02.png……`。

建议数量：

- 3 分钟以内：`4—6` 张高价值插图。
- 3—5 分钟：`6—9` 张。
- 5—8 分钟：`8—12` 张。
- 数量只是参考，最终按语义关系决定，不为了达到数量强行加图。

完成标志：`insert-frames.md` 中所有资产状态均为“已完成 / 已验收”。

## 阶段 4｜分镜图生成标准

每张图生成前必须明确：

- 对应台词。
- 画面目的。
- 人物布局模式。
- 主体数量。
- 是否需要准确文字。
- 字幕安全区。
- 输出文件名。

文字策略：

- 固定、简短、必须成为视觉主体的词，可以尝试直接生图，例如“史诗级改版”。
- 产品名、模型档位、数据和长句默认不直接生进图片，使用空白卡片后期叠字。
- 如果必须生成文字，生成后先逐字核对，再进入正式目录。
- 英文产品选项应保留英文，并配中文解释，不能只给英文。

验收标准：

- 比例正确，正式插图为 `16:9`。
- 人物位与脚本规划一致。
- 底部字幕安全区完整。
- 中文无错字，英文拼写和顺序正确。
- 画面只有一个核心关系。
- 没有多余 Logo、水印、人物或装饰模块。
- 与已确认主视觉的颜色、材质和光效一致。

## 阶段 5｜剪辑执行顺序

1. 先完成真人口播粗剪，删掉错误、重复和过长停顿。
2. 生成并校对完整字幕，确定最终时间轴。
3. 按分镜清单放入章节标题卡。
4. 放入真实录屏和截图，完成关键点击、放大和标注。
5. 放入生成式分镜图，按语义点亮、缩放或逐步出现。
6. 添加关键词大字，避免与底部字幕重复堆叠。
7. 统一人物小窗的位置、大小和边框。
8. 最后添加音效、转场、背景音乐和整体调色。
9. 完成一轮无声检查和一轮带声音检查。

为什么先做字幕时间轴：只有口播节奏确定后，录屏、分镜图和大字的插入点才不会反复移动。

## 阶段 6｜成片验收

### 内容验收

- 每个强结论有截图、演示或来源支撑。
- 案例演示展示了真实过程，不是“输入一句话就完美完成”。
- 前 15 秒说清这条视频能解决什么。
- 章节顺序和脚本一致，没有漏段。

### 画面验收

- 开头和结尾有完整真人画面。
- 人物小窗位置统一，不在不同段落中跳动。
- 每 `3—6 秒` 至少有一次有效的信息变化，但不为了变化乱切画面。
- 截图与录屏中的文字在手机端可以看清。
- 红圈、箭头和高亮只指向当前正在讲的内容。
- 分镜图没有错字、错误顺序或无关元素。
- 底部字幕不遮挡人物、按钮和关键信息。

### 平台与隐私验收

- 检查前 10 秒、封面、标题和标签的风险词密度。
- 录屏中没有真实姓名、账号、聊天记录、客户数据或联系方式。
- 演示数据全部为模拟数据。
- 不出现下载、登录、代理或外网配置教学。

## 五、以后每条视频的标准交付物

每个作品文件夹建议固定为：

```text
作品/YYYYMMDD_选题名/
├── 脚本.md
├── 演示素材/
│   ├── 原始数据或文档
│   └── 脱敏后的演示文件
├── 录屏素材/
│   └── 按分镜编号命名
├── storyboard/
│   ├── insert-frames.md
│   ├── scene-01.png
│   ├── scene-02.png
│   └── ...
└── 成片/
    └── 定稿.mov
```

说明：短视频原始视频、录屏和最终成片默认不进入 Git；最终确认的分镜图片和脚本文档进入 Git。

## 六、关键控制点

以后不再直接从“脚本定稿”跳到“开始生图”。中间增加两个必须确认的节点：

1. **分镜清单确认**：确认每一段到底用真人、录屏、截图还是生图。
2. **资产清单确认**：确认所有待录制、待截图和待生成的文件已经列全。

只有这两个节点确认后，才批量生成正式分镜图。进入正式剪辑后，原则上只允许修图，不再新增语义段落或临时改变整套视觉风格。
